---
title: "VL6180X Multi-Instance I²C Component"
---

The VL6180X is an I²C time-of-flight sensor with a default address of `0x29`. This component is an example of
handling multiple identical I²C devices that power up at the same address. Its driver and tests are in the
[ESPHome source tree](https://github.com/esphome/esphome/tree/dev/esphome/components/vl6180x).

## Address Assignment

Each sensor needs a separate XSHUT/CE GPIO when changing its address or when using multiple sensors. At startup, the
component holds all configured sensors in shutdown, releases and initializes them one at a time at `0x29`, then assigns
each sensor its configured address. This avoids address collisions during initialization. The configuration schema
rejects duplicate addresses and shared or missing enable pins in multi-sensor configurations.

```yaml
# Example configuration with two VL6180X devices on one I²C bus
vl6180x:
  - id: near_sensor
    address: 0x29
    enable_pin: GPIOXX
    range:
      name: "Near Distance"

  - id: far_sensor
    address: 0x30
    enable_pin: GPIOXX
    range:
      name: "Far Distance"
```

The component keeps a code-generation-sized static registry of configured instances. This avoids dynamic vector
allocation while still allowing the first component instance to sequence initialization and coordinate whole-bus
recovery.

## Non-Blocking Measurements and Recovery

Range and illuminance measurements advance through short I²C state-machine steps in `loop()`. The component does not
wait synchronously for a measurement to finish, so it does not block ESPHome's main loop. Illuminance reads use their
own configurable interval and queue behind a range measurement when the sensor is busy.

After a configurable number of consecutive I²C or measurement failures, the component enters recovery. One instance
coordinates the shared XSHUT sequence, waits for any active measurements to finish, and reinitializes the sensors. Failed
recovery attempts are retried, with a longer delay after the configured retry count.

The optional GPIO interrupt input can be used to detect sensor readiness. Without it, the driver polls the interrupt
status register over I²C.

## Configuration Coverage

The integration tests cover the default ESP-IDF build, Arduino, a multi-sensor setup with separate addresses and enable
pins, and the legacy `sensor: platform: vl6180x` syntax. These tests use ESPHome's default framework versions.
